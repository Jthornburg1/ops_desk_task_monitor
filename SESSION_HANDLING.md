# Session checks and expiry

OpsDesk checks the Amplify session at launch and whenever its scene becomes active. The adapter asks Amplify to fetch the session, allowing the SDK to refresh expired tokens, then checks the Cognito token result. The SDK's `isSignedIn` flag alone does not establish a usable session. Tokens stay managed by Amplify; the app does not implement token parsing, cryptography, or token storage.

A successful token result permits account restoration. A session-expired or not-authorized SDK error removes the dashboard and clears the displayed account ID/email, with a message asking the user to sign in again. Saved per-account task overrides remain. When the user taps Sign in, the app first uses SDK sign-out to clear retained signed-in state, then opens hosted sign-in. This reset can present the provider's sign-out page. A full or local/partial sign-out permits sign-in; a failed reset offers retry. Browser cookies may still permit SSO if provider sign-out was incomplete.

Other SDK errors are treated as verification unavailable, not proof of expiry. At startup, the app offers a session-check retry before opening sign-in. With an already displayed dashboard, it retains the account/tasks and shows a retry message. JSONPlaceholder remains a public API; retained local UI is not a claim of server authorization. Repeated checks and auth operations are serialized by the ViewModel's existing busy guards.

This increment checks on launch/foreground and explicit retry. It does not continuously monitor expiry while the app remains active, subscribe to Amplify Hub events, or add a protected-API 401 recovery path. Remote revocation can remain undetected until the SDK needs to refresh its cached tokens. No forced refresh is requested on every foreground transition.

Automated tests exercise SDK token success/expiry/failure, reauthentication reset and retry, account clearing, offline verification/recovery, and overlapping operations. Live refresh-token expiry and browser recovery still require manual acceptance testing; no token lifetimes or Cognito console settings were changed. Test expiry by letting or deliberately causing the refresh session to expire in a controlled test account, then relaunch or background/foreground the app and check the recovery flow. A short-lived access token alone should refresh silently while its refresh token is valid.
